Fresh offline packages bind runtime source `31545cd7898e5ef7d92b3b9b09e4bd17246ae349`. Every emitted server JavaScript module and protocol schema is compared before each case; separate artifact metadata binds all installed package JavaScript to the clean build. No production, shared runner, schema, catalog, map or cumulative manifest changes are included.

The normative scope is Map26 `transactional.idempotency.key-grammar`, together with actual carrier placement: singleton and batch use exactly one HTTP `Idempotency-Key`; sequence members use their body `idempotencyKey` and the sequence carrier rejects a stray HTTP field. This is not a new header requirement for sequences.

The HTTP case submits absent, equal-repeated, different-repeated, empty,257-character, quoted, internal-whitespace, punctuation and Latin-1 non-ASCII key fields through both singleton and batch routes. Exact raw request metadata retains field multiplicity and values, without persisting Authorization. Valid one-character and256-character keys, mixed allowed alphabet, normalized-neighbor probe keys and case-distinct keys then create independent full literal records; each retry returns the byte-identical receipt. Exact receipt key echoes and distinct receipt IDs rule out truncation, quote stripping and case folding. Every successful creation appears once in the fully collected finite feed.

The sequence case has no HTTP key. An invalid later key must prevent the valid first member from executing. Missing, empty,257-character, quoted, internal-whitespace, JSON-string padding, punctuation and non-ASCII member keys, repeated member keys and a stray carrier HTTP key are refused. First and second subjects remain404 and the feed stays empty. Valid min/max, case-distinct and neighboring normalized tokens, including a previously unexecuted valid first member key, then succeed with exact full results/retries and exactly one group per admitted key. This does not test duplicate JSON object members or lone surrogates, which belong to another unit.

Internal HTTP whitespace and sequence string padding are tested; extra transport OWS around an HTTP field is not presented as an application-token normalization test.
