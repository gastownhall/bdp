# Packed Accept refusal

This NEW cohort uses an ordinary offline-installed Transactional target and the actual custom fixture bytes. A valid new create whose Accept is text/plain receives an empty 406 before any key binding or state/feed advance. The SAME key with application/json then executes once; a matching retained request with unacceptable Accept also receives empty 406 without changing the terminal receipt or adding effects.

The exact receiving and JSON-mutation admission clauses in docs/specs/bdp.md govern these two branches. Authentication, distinct-request conflicts, pending receipts, q-value permutations, other carriers and whole-profile qualification are outside this finite cohort. No administrative or clock fixture is used.

Raw request bodies and response bytes are retained; authorization credentials are resolved privately and omitted from the report. Installed modules and packaged schema are byte compared before and after execution; all owned process/store cleanup is attempted independently on failure.
