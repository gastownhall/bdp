# Packed batch and set semantics

This standalone test binds the actual offline-packed `e2bcb59a3b4ec97a6125d24e693a07e7ebbf16bf` runtime through the existing installed IPC launcher, actual fixture bytes, ready configuration metadata, and exact raw HTTP executor. Each of three cases starts its own store with ordinary public configuration, one writer, unchanged limits and clock. Every server JavaScript module and protocol schema is compared with the clean emitted build. No runtime, shared runner, schema, catalog or cumulative manifest changes are included.

- Local references: one real batch creates two labeled Beads, updates `@first`, and creates a Link from that label to a PinnedReference whose `uri` is `@second`. The opaque pin is preserved byte-for-byte, without pretending it is the target's actual revision. Complete literal postimages and operation order, first-class reads, changed source revision, and exact six-Event type/subject order and graph-fact data are checked.
- Rollback/no-op: a preceding staged update is rolled back by a later cardinality failure. The failed receipt has no results/next/effectPosition, and an equal-key retry returns its exact body. Full original records and complete finite feed remain unchanged. An all-noop two-operation batch returns both updated entries at original revisions, current requiredPosition and no effectPosition/group; a mixed batch returns both entries but advances once and emits only the changed Bead's update.
- Cardinality: exactly two matching records satisfy the lower endpoint of [2,3] and upper endpoint of [1,2], with literal ordered postimages. Below-min and above-max batches each stage a separate label change before failing; both complete transactions roll back, including that preceding change, with no new group or position.

The first run passed rollback/no-op and cardinality; the local-label case reached its final feed assertion and failed an authored expectation that linked Event subjects were the endpoint Beads. The agreed HTTP Event model uses the Link subject with explicit endpoint data. The expectation was corrected and strengthened with complete graph-fact data; only that affected case was run again and passed. The original failed run/source/raw observations remain retained. There is no claim of one final three-case run or a replay of earlier conformance cohorts.

Owner evidence is under `bdp-write-product-reset-20261020/batch-set-installed-product`: all raw responses, exact source snapshots, failed and successful receipts/logs, fixture/configuration/package bindings and cleanup. Each cohort has a 20-second abort watchdog, each request 5 seconds, at most64 requests and1MiB response bodies. The existing child launcher bounds startup/close at10 seconds and combined child logs at64KiB; the outer owner watchdog is90 seconds with1MiB channels.
