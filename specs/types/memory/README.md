# Memory Bead and Link Types

[Memory Bead and Link Types](memory.md) is the current standalone review draft. It defines eight Bead Types and five Link Types for knowledge, replacement, governing rules, necessary dependencies, defining structure, and applicability.

| Bead Types | Link Types |
| --- | --- |
| Memory; Constraint; Policy; Decision; Procedure; Requirement; Scenario; Specification | References; Superseded By; Requires; Defines; Subject To |

The [full proposal](https://github.com/gastownhall/beads/issues/7661) mirrors this document and links [source PR143](https://github.com/gastownhall/bdp/pull/143). Publication does not install Types, adopt a protocol profile, qualify a runtime or move a consumer pin.

The structured catalog preserves title/body/status, the reserved applicability extension, correlated endpoint pairs, Type refinement, ownership and graph rules. [The publication boundary](memory.md#publication-scope-and-deferred-specification-work) names the remaining representation and lifecycle work. Historical schemas, definitions, fixtures and receipts remain exact earlier artifacts; they do not validate the current catalog unless regenerated against its selected source.
