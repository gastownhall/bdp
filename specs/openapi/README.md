# BDP v0.1 informative OpenAPI operation catalog

Start with the [canonical command map](commands.md) and [CLI/wire exceptions](../../docs/cli-design/wire-correspondence.md). The catalog groups 19 specified public command signatures, with 35 wire-case families:26 GETs,26 corresponding HEADs and9 POSTs. Revision/view/projection cases are command options; the matrix is not a proposed 61-method public client interface.

This draft describes selected retained Core/Write, finite JSON Events and separately selected optional History, Resource projection1, atomic-batch1 and narrow exact-definition lookup. It does not advertise a provider, implement a navigation adapter, complete a Go SDK handoff or amend the selected contract. Types inventory/lifecycle, Query/Graph, richer selection/set batch2, sequence, public receipts, replication and SSE remain excluded.

[bdp-v0.1.openapi.json](bdp-v0.1.openapi.json) deliberately has `paths:{}` and reusable `components.pathItems`. BDP discovers absolute operation/inventory URLs and accepts canonical Resource/continuation URLs; it does not prescribe fixed deployment paths. The draft `x-bdp-navigation` family is informative authoring metadata, not a wire capability, request field or a standardized generator adapter. Query-selected views have separate catalog signatures but share their real canonical URL. A production client must select/verify contract, Scope, capability, context, authorization and exact discovered URL before dispatch.

[bdp-v0.1.tooling.openapi.json](bdp-v0.1.tooling.openapi.json) is a **synthetic .invalid tooling fixture**, with conventional paths bound from [bindings.json](../../fixtures/openapi/bindings.json). `x-bdp-exact-fixture-url` preserves original URL/query spelling, including escaped IDs and opaque query components on mutation URLs. Ordinary OpenAPI code generators do not implement those dynamic binding semantics. This fixture and the Node unit do not exercise a real service, external parser/code generator, network request or production adapter.

Base wire schema references remain external `../profiles/core/bdp-v0.1.schema.json#/$defs/NAME`. The separately selected id-root1 create/batch variants reference `../profiles/write/id-root-v1.schema.json`; they reuse the same URLs and result schemas. The canonical schema's `$id`, `$schema`, internal references and distribution mirror are neither copied nor rewritten. This OpenAPI3.1.1 document names the JSON Schema2020-12 dialect. Tooling must support external schemas, boolean schemas, union/reference carriers, conditionals and unevaluatedProperties; a successful language-type generation alone would not validate admission or conformance. Unused inherited definitions in the bundle do not become operations.

[coverage.md](coverage.md) lists each method, native navigation, request/result, media, fields/errors and source/CLI clauses. Bodyless HEAD/304/405/406/412/500 are explicit and not default Problem bodies. Alias resolution is307 with Location; writes are200 with no operation-target ETag/Location. RFC9457 Problems retain application/problem+json; selected successful BDP JSON uses application/vnd.bdp.v0.1+json. Scope landing uses ordinary HTTP, with no vendor-media Accept requirement; its optional human200 body is deliberately untyped in this catalog.204 and machine-discovery navigation remain explicit, and vendor media is selected after following service-desc. Unknown authentication schemes and deployment URLs are not invented.

Projection parsed-query definitions describe decoded values; `fields` travels as one JSON-encoded query value. Protection of whole References, authorization before masking, omitted optional paths and original-index array semantics remain prose obligations. Schema arms overlap, so projection response alternatives use anyOf and explicit request-selection metadata; a no-fields request still requires full output. Native query repetition/extra fields, complete History, exact-definition wrapper ownership, key replay/owner correlation and cursor fences need semantic implementation beyond this catalog. Event pages gain no invented Resource/Collection-kind header. CORS and optional validators retain their native conditions.

Generate/check with the repository's exact Node24.22.1:

```sh
node scripts/generate-openapi.mjs
node scripts/generate-openapi.mjs --check
node --test scripts/openapi.node-test.mjs
```

The Node unit is outside the Vitest glob. The generator formats its JSON through the repository-pinned local Biome2.5.7, using a bounded subprocess with no shell or network; the frozen workspace dependencies must already be installed. It checks deterministic regeneration, reference resolution, mirror/source custody, closed eight-target correspondence, explicit bodyless/media branches and authored positive/negative offline exchanges. Strict Ajv checks validate positive fixture body shapes against the canonical schema, with `validateFormats:false`; format assertions remain in the existing full-format schema suite. Wrong whole-Reference keys are explicit negative controls. It is **not** an OpenAPI meta-validator, generated-client compiler, provider/CLI/server or transaction test. Generation and the Node unit do not perform external OpenAPI meta-validation; separate evidence is required. Code generation remains a separate qualification. The unit uses the existing pinned root Ajv dependency; no new dependency is added.

Source fingerprints are deliberately approved constants at authoring base e23aec722763e967d3bde08caf96657069b39ead plus the reviewed id-root1 amendment. Any selected normative/CLI/schema drift stops generation. There is no moving-HEAD lookup or automatic fingerprint refresh. A source change requires paired mapping review plus intentional fingerprint update, never rehash-only adoption. Source/contract review and Trish's receiving review precede ready/landing claims; actual Go-client navigation, schema validation and independent tool compatibility remain future handoff work.

Known source wording drift: some per-command CLI tables still describe field selection as rendering. The common [native projection clause](../../docs/cli-design/bdp-cli.md#L469) and [read mapping](../../docs/cli-design/reads-and-paging.md#L8) govern current/exact Resource projection; catalog pointers select those common clauses. This artifact does not edit the shared CLI specification.

Cache-Control is conditional: authorization-dependent responses require `private, no-store`, including alias redirects, landing204 and applicable Problem responses. The catalog does not invent a representation for bodyless405/500. An advertised aliases navigation base supplies alias URLs; it is not a defined alias inventory operation or an additional route.

New allocation documentation reuses the Memory experiment's [human-readable table conventions](../../docs/cli-design/authoring-formats.md). External canonical schemas and explicit protocol constraints retain their authority; no whole-DSL conversion is claimed.
