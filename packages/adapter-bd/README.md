# bdpbd projected revisions

bdpbd-projected-resource-v2 uses IEEE-754-binary64-ECMAScript-JSON numbers: native JSON is parsed into JavaScript binary64 values and finite numbers are serialized with ECMAScript JSON.stringify (shortest round-trip form, negative zero as 0). The preimage is the complete projected Resource excluding only its revision member: id, type, common metadata, attribution when present, properties, and Link endpoints when present. Objects use UTF-16 code-unit lexical key order recursively, arrays retain order, and strings use ECMAScript JSON.stringify escaping. The UTF-8 bytes are SHA-256 hashed and encoded as unpadded base64url with the sha256_ prefix. This local discipline does not claim RFC 8785/I-JSON conformance: the reader has no duplicate-member or lone-surrogate admission guarantee. Adding common metadata to the complete projected Resource changes content-derived revision tokens, including when metadata is empty; existing tokens are historical and must not be relabeled. This v2 discipline introduces no discovery member. Read observations cover numeric values actually returned by the supported bd projection, not write admission or arbitrary decimal preservation.

The exact declaration is bound in the portable conformance fixture under `oracles.numeric-model.declaration`; the successor observation tests require agreement with this document.
