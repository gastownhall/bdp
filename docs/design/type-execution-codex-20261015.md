# Native Codex review

Reviewed immutable snapshot of docs/design/type-cli-implementation-notes.md with specs/types.md and docs/design/type-cli-proposal.md. No source implementation qualification.

1. **High — slice 2/slice 3 dependency is not executable as written.** Implementation notes lines 123–124 establish all four usable foundation definitions before owned ConformsTo and matching. But specs/types.md §§2.1–2.3 and §3.10 make BeadType/LinkType conformance and inherited ownership part of the seeds themselves; the seed is not four independent descriptors. A temporary hard-coded inheritance or ownership interpretation could become a second authority. **Fix:** include the minimum exact owned-snapshot representation and closure reader needed by the seed in slice 2 (or explicitly combine that foundation part of slices 2–3); reserve general authoring, closure indexing/query convenience, and specialized relationships for the later slice. The tagged-source audit can start now; this only gates runnable foundation behavior.

2. **High — deferred specialized deletion does not bound ordinary deletion.** Lines 125, 146–147 and 172 defer deletion/retention policy but the experiment makes Types normal Beads reachable through generic operations. A generic delete/purge/retype of a definition or seeded metatype can make the exact definitions required by current instances or historical conformance unavailable. Saying bd type delete waits does not prevent bd delete/batch/storage cleanup. **Fix:** specify an experimental guard across all mutation paths: retain every exact definition and owned Link revision needed by accepted affiliations/closure, and reject unsupported destructive operations. Test generic deletion/retyping and historical read/matching after attempted removal. This is an experiment safeguard, not a decision of eventual product removal policy.

3. **Medium — slice 1 has no explicit partial-rollout boundary.** Lines 122 and 144–147 defer legacy/wire decisions and forbid full profile advertising but do not state how incomplete support is enabled. Slice 1 changes model, persistence, wire and CLI before definitions are usable. A default-on intermediate change may break Preview 2 catalog consumers even if later slices repair it. **Fix:** each early PR must identify its enabled surface and whether it is mergeable dormant machinery or an opt-in disposable-workspace experiment; retain default legacy behavior until its compatibility gate passes. Add serialized old-data/read-write compatibility fixtures at the agreed boundary. Do not invent a new profile identifier until chosen.

4. **Medium — acceptance needs adverse historical-closure and direct mutation cases.** Lines 59–68 and 137–142 cover happy history and one stale retype but not (a) missing exact ancestor/Link revision, (b) diamond conformance with repeated ancestors and two different revisions of the same ancestor, (c) owned-declaration mutation with a stale source precondition, or (d) a failed definition-plus-declaration transaction publishing no partial definition/index state. These are where a live-adjacency shortcut or cache keyed only by identity silently destroys the promised semantics. **Fix:** add a small outcome matrix: missing exact data fails closed without latest fallback, exact revisions remain distinct, diamond paths deduplicate consistently, failed changes preserve old owner state and matching results. No implementation performance target is needed yet.

No branch-flow contradiction found: lines 93–96 explicitly permit coordinated prerequisite merges while retaining graph-preview2 as each branch's starting point. Review scope does not require the entire lifecycle or graph-constraint system before the bounded experiment.
