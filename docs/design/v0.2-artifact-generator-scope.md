# v0.2.3 artifact generator — scope

Seal: v0.2.3 (fresh seal — structural correctness, NOT byte-identical to the sealed v0
cohort; confirmed by Connie/#404 2026-11-23). The v0.2.2 `@ca298b04` pin stays the
conformance gate's reference. The gate consumes BOTH the JSON Schema bundle (draft
2020-12) and the OpenAPI 3.1.1 catalog; `$defs` naming keeps the `#/$defs/…` scheme.

Status: draft for review (lydia). Purpose: define exactly what a generator must emit
from `specs/src/` so the reshape can retire the hand-maintained `specs/profiles/` +
`specs/types/` layout and repoint conformance at generated artifacts.

## 1. Target state

`specs/` holds two directories, nothing else:

- `specs/src/` — hand-authored Lumen (`core/core.lumen`, `bdp.md`, `packs/*`). The sole
  source of truth.
- `specs/generated/` — everything derived from `src/`, written only by the generator,
  never hand-edited.

Retired to history (which moves under `docs/`): `specs/profiles/`, `specs/types/`,
`specs/openapi/`, and the per-profile schema/fixture JSON they host today.

## 2. What the generator must emit (replacing the v0/v0.1 derived set)

Measured from the current pipeline (5 generators reading the old profile markdown via
`bdp-schema:` markers in a custom "markdown JSON-Schema DSL"). The v0.2 generator reads
Lumen instead and emits:

| # | Artifact | Replaces | Format | Hard consumer contract |
|---|----------|----------|--------|------------------------|
| A | Core JSON Schema bundle | `bdp-v0.schema.json` + `bdp-v0.1.schema.json` (+ their `packages/protocol/schemas/` byte-equal mirrors) | JSON Schema 2020-12, one bundle of named `$defs` | `packages/protocol` resolves validators by exact `$ref` into `$defs` (`READ_VALUE_SCHEMA_REFS`, etc.) — **the `$def` names are a contract** |
| B | Feature-supplement bundles | `id-root-v1`, `delete-modes-v1`, `historical-update-v1`, `types-v1`, `callables-v1`, `issue-callables-preview-1` | JSON Schema 2020-12 bundles | protocol + openapi `$ref` into them |
| C | OpenAPI catalog | `specs/generated/openapi/core.openapi.json` | OpenAPI 3.1.1 — the 13 primitives as **populated path operations** (the gate keys on these), schemas embedded in `components` | the conformance gate (op/fault denominator) |
| D | Human companions | `coverage.md`, `commands.md`, `read-contracts.md`, `write-contracts.md`, `bdp-v0.1.schema.md`, the Markdown reference | Markdown | docs; `lumen-to-markdown.py` already emits the reference |
| E | Callable catalog | `packages/bd-domain/catalog/issue-callables-preview-1.json` | callable-catalog JSON | `packages/bd-domain` |
| F | Ownership stamps | `x-bdp-schema-definitions` / `x-bdp-schema-sources` | keys on A/B | provenance checks |

**core.lumen already specifies the lowering** that produces A–C: Appendix B/C (lines
~1703–1784) maps Lumen → JSON Schema (`type is string`→`{type:string}`, records →
`object`+`required`+`additionalProperties:false`, `A|B`→`oneOf`, closed DU →
`oneOf`+`discriminator`, `ref<T>`→`$ref ResourceRef`, `/// jsonschema={k=v}` merged as
keywords) and `## op` + `/// openapi={…}` → one OpenAPI path-item/operation. The
annotations are already in the source; today only `lumen-to-markdown.py` consumes Lumen,
and it drops the `jsonschema`/`openapi` hints.

## 3. Out of scope for the generator (owned elsewhere)

- **Conformance scenario vectors** — `packages/conformance/catalog|matrices|fixtures/*`
  are hand-authored prose-citation + execution matrices (`requirements[].selectedText`
  quoting the spec). They are NOT derivable from the IDL and stay with the conformance
  suite (the conformance owner's domain). The generator feeds them *schemas to validate
  against*; it does not produce the scenarios.
- **Types review graph literals** — `intrinsic-*.json`, `*.publication.json` (sha256
  pins), `*.properties.schema.json`, descriptors. A Type-registration/affiliation graph
  the Lumen appendix does not yet describe lowering to; the Types pass in core.lumen is
  still open. Treat as a later generator phase, after the Types pass lands.

## 4. Constraints / decisions

1. **Seal — RESOLVED (Connie/#404, 2026-11-23): FRESH seal, structural equivalence, NOT
   byte-identical to the sealed v0 cohort.** The generator chases structural correctness, not
   byte-for-byte reproduction; key ordering and serialization are free. (The v0.2.2
   `@ca298b04` cohort stays the gate's reference until the version-skew call lands — §8.)
2. **`$defs` naming — RESOLVED for the gate (Connie): keep the Lumen type names**
   (`#/$defs/Resource`; cross-bundle `core.schema.json#/$defs/Resource`). The gate consumes the
   generated bundle fresh, with zero legacy-name dependency. NOTE (a protocol-migration call,
   not a gate blocker): the 104 generated names (Pascal-case) and the 218 names in the legacy
   `bdp-v0.1.schema.json` that `packages/protocol` validates against (camelCase) overlap in
   **exactly one** (`selector`). So protocol's existing ref-maps must be repointed to the new
   names (or get a compat-alias shim) as part of the 0.2.3 cutover — tied to the version skew
   (§8). The earlier "emit the exact legacy names or protocol breaks" line is withdrawn.
3. **`bindings.json`.** The old OpenAPI generator reads a hand-authored route/binding
   table (`fixtures/openapi/bindings.json`). The v0.2 `/// openapi` annotations carry this
   (`pathItem`/`params` are all present); the new emitter derives literal paths from a route
   map (`ROUTES`) off the operationIds, so no separate binding table is needed.
4. **Implementation language — RESOLVED: Python.** With no byte-fidelity requirement there is
   no need to match Node's `serializeSchemaJSON`, so the generator extends the Python toolchain
   (`lumen-to-jsonschema.py`, built on `lumen-to-markdown.py`'s parser) rather than porting to
   Node.

## 5. Proposed shape

One generator over `specs/src/` emitting into `specs/generated/`:

```
specs/generated/
  reference/        # Markdown reference (core.md + per-pack) — extends lumen-to-markdown
  schema/           # A + B: the JSON Schema 2020-12 bundles
  openapi/          # C: the OpenAPI 3.1.1 catalog + coverage/commands
  catalog/          # E: callable catalogs
```

`packages/protocol/schemas/` either becomes a thin re-export of `specs/generated/schema/`
or is generated into as a mirror (as today), asserted byte-equal.

## 6. Sequencing (status 2026-11-23)

1. **Schema bundle (A) — DONE.** `lumen-to-jsonschema.py` lowers core.lumen to the core
   2020-12 bundle (104 defs, 0 unlowered, 0 dangling). Structural, not byte-exact (fresh seal).
2. **Feature bundles (B) — DONE.** `generate-schema-bundles.py` emits core + per-pack bundles
   (issue 52 / memory 12 / ops 7 / stdlib 17) with cross-bundle refs.
3. **OpenAPI (C) — DONE.** `lumen-to-openapi.py` emits the 13 primitives (3.1.1, populated
   paths, embedded schemas); pack callables → catalogs (`lumen-to-callables.py`).
4. **Companions + catalog (D, E) — DONE** (markdown reference + callable catalogs).
5. **Gate wiring — DONE for the editorial gate.** `check-generated.py` (drift + `$ref` validity)
   wired into CI; `check-spec-editorial.py` repointed onto `specs/generated/`.
6. **Hand conformance the generated schemas; retire v0/v0.1 TS tests as covered** — Connie
   (#404) has the full set; the `packages/protocol` ref-map repointing (§4.2) is the first
   dependency, and it ties to §8.
7. **Retire `profiles/`/`types/` + move history to `docs/`** — after 6.

## 7. Contract questions — ANSWERED (Connie/#404, 2026-11-23)

1. Artifacts consumed: **BOTH** the JSON Schema bundle (draft 2020-12) and the OpenAPI 3.1.1
   catalog — OpenAPI = op/fault coverage surface, JSON Schema = wire-payload validation.
2. `$defs` naming: **keep the Lumen type names** (§4.2); no legacy-name dependency in the gate.
3. Scenario vectors: **stay hand-authored**, derived from `/// normative:` content, with
   already-run normative tests reflected back into `specs/src` normative metadata (shared action).
4. Byte-stability: **fresh seal — structural, not byte-exact** (§4.1).

## 8. Open — for Donna (version skew)

The conformance gate pins **v0.2.2 `@ca298b04`** as its reference, but the generated artifacts
are **v0.2.3**; both cannot hold. Resolve one of: (a) the gate **re-pins to 0.2.3** and tracks
the generated artifacts (one source of truth — cleanest), or (b) it stays v0.2.2 and the
generator also emits a v0.2.2 bundle. This also gates the `packages/protocol` ref-map repointing
(§4.2) and a 1-row op/fault denominator reconciliation (52 generated rows vs 51 at v0.2.2 — the
0.2.3 HTTP-binding delta).
