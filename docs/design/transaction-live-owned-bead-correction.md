# Direct correction of an owning Bead

The authentic source-private `correctLiveBeadVersion` companion now accepts a current Bead with a nonempty owned set when correcting its properties or common metadata. Its exact base is PR212 `93055f2914ebf89dd611284a0583688cb034c089`. Public facade keys, HTTP routes, Operations, configuration, CLI and package exports are unchanged, and administration still creates no Mutation Receipt.

Specification6456–6500 distinguishes a direct property/common-metadata correction from a source revision induced by an owned-Link operation. This unit implements the former. It removes the explicit nonempty-owned-set refusal, then uses the existing ordinary `updateBead` evaluator and actual installed schema validator. The evaluator rebuilds the complete inline set from current outgoing Links; a new owner assertion requires that whole set to remain deep-equal to the previous one. The caller cannot supply an owned set. Every first-class Link, revision, metadata, attribution envelope and endpoint pin remains unchanged.

The successor changes its own properties and/or metadata and gets a fresh Bead revision. Its single `updated` fact carries the corresponding complete root replacements and `previousRevision`, with no `ownedLink` delta. An unchanged correction is refused rather than silently tombstoned. Partial patches, stale guards and supplied owned sets are still refused. Bead tombstone preparation and ordinary deletion safety are untouched; a live incident Link still prevents this administrative Bead deletion.

The same atomic pipeline retains the successor and plans/purges the selected previous Bead version. The historical cascade runs from an erased Link version to source versions that inlined it. It does not run backward from a Bead record to its unchanged Links. Tests therefore require exactly one Bead erasure record, complete unchanged inline and first-class Link records, and retained Link versions. The shared ledger, lineage, digest, receipt, Snapshot, cache, replay and Event fences remain in force.

Thirteen distinct NEW focused cases pass across retained runs: properties/metadata/both corrections with two Links and a pin; wildcard ownership; unchanged/stale/partial/supplied-set/tombstone refusals; before-commit rollback; postcommit uncertainty fencing/reopen; installed property-schema refusal; and actual HTTP/SSE correction/reopen. One inherited universal refusal row was narrowed to retain Link-via-Bead-API rejection; its changed assertion passed separately. No unrelated old positive cohort was replayed, and there is no final all13 single-run claim.

The HTTP case records18 responses and one new SSE group at position3. It observes the complete unchanged owned set, both first-class Links and the untouched target; old Snapshot, ordinary continuation and finite changefeed refusal; a valid exclusive Event cursor; erased original update receipt plus same-key replay; and the same epoch/current graph after reopen. The administrative call remains private, outside BDP HTTP. This is source-built runtime evidence, not packed installation evidence. Owner digest assertions reuse the existing canonical serializer rather than claiming a new independent JCS implementation audit.

The first HTTP fixture attached after the first of two prior groups and correctly observed an extra earlier group. Its successor initially encoded the captured `next` URL as though it were a checkpoint and received400. Both failures, exact tested source snapshots and cleanup observations remain retained. The corrected case follows the actual opaque `next` URL before attaching. The12 already-passed owner cases were not repeated.

Commands, exact source/module bindings, raw stdout/stderr, JSON results, watchdog/EOF/reap/group observations and cleanup evidence are in `bdp-integration-logs/bdp-write-product-reset-20261020/live-owned-bead/implementation-validation.json` and its evidence index. Test-owned stores are independently removed even after close or assertion failure, preserving primary and cleanup causes.

Owned-Link replacement, endpoint rewriting, owned Bead tombstone cascades, restore/newEpoch, general authorization views, optional History, packed installed owning-Bead correction, all erasure obligations and whole-profile/runtime-fit claims remain outside this unit. The frozen PR212 source/evidence, agreed specification, main/release/pins and proof-stage boundaries remain unchanged.
