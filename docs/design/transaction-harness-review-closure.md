# Private Transactional harness review closure

The cumulative Transactional carrier remains source-private. H1b adds private exact transport and four bounded installed observations; all four remain partial and the 250 required contracts remain visible. No public Transactional runner admission or whole-contract credit follows.

The package guard now inspects actual module exports and the closed package subpath map, rather than searching source text for private symbol names. The configuration test retains pre-setup refusal for malformed exact configuration, permits valid Read+Update and private Transactional modes, and keeps the ordinary-runner private-brand boundary.

The planner now returns `transportAdmission: "private-exact-available"` for Transactional alongside structural `ready-unexecuted` rows. This is not a new public API or an executable admission flag; it identifies the actual private transport. Coverage observation status is independent, and whole-contract flags remain false. Coverage-binding tests require an actions array and strict structural equality, preventing an omitted assertion list from comparing equal to an undefined property.

Two review suggestions are bounded rather than generalized into new mechanisms. Cumulative catalog IDs have exactly two guarded private callers; hypothetical future-profile hardening is deferred until another caller exists. Canonical selection refusal is a factory-identity boundary, not an independent content-completeness validator: both copied and trimmed records are refused because neither is loader-branded. Existing coverage follows from the immutable canonical loader, not the trimmed-record probe alone.

Read+Update retains its existing carrier and transport behavior. Protocol/catalog/public profile admission are unchanged; cumulative Transactional qualification remains open.

## Installed observation boundary

The private launcher supplies explicit canonical Scope, caller-provisioned isolated store directory, captured contract artifacts, and generated credentials to the installed child over inherited IPC. The child reports its actual immutable runtime, payload, contract, authentication and policy identities. Preparation and reopen compare those facts before actions. This is configured-target evidence, not cold discovery: required Transactional discovery and the remaining catalog obligations still need qualification.

The runner registers a receipt target only from a schema-valid receipt `/id` captured alongside complete exact request and response wire evidence. It retains the original source action, credential handle, response digest and session identity. Receipt GET/HEAD uses a one-target raw route table bound to the current validated physical session; it records a separate dynamic configuration digest without changing the run's base configuration. Reopen preserves original receipt provenance while rebinding ordinary and dynamic traffic. These metadata fields are excluded from legacy report-v3 types, runtime assertions and serialization.

Four small fixtures exercise atomic commit and ordered Events, failed-batch rollback, retained completed/failed receipt reads after reopen, and a retained failure after graph state changes. Collections declare limit 32 and require no next page; Event inventories also require no next page. They use at most six induced Scope Events per row. Requests use header/body caps of 16,384/65,536 bytes; response header/body caps are 65,536/1,048,576 bytes with a 2,097,152-byte wire-evidence ceiling. This observation does not qualify larger receipts, general receipt paging, dependency/alias behavior, catch-up, Snapshot, changefeed, owned transitions, or the remaining required contracts.

The new metadata-comparison whitelist entries (`bdp-scope-epoch`, `bdp-authorization-view`, `bdp-scope-position`) compare existing response headers using the existing assertion grammar. They do not expand request authority. Session cleanup aborts and drains registered dynamic requests before child shutdown; installed shutdown or IPC disconnect releases the owner for a subsequent ordinary reopen. Forced termination remains failure, not successful observation.
