# Private Transactional harness review closure

The cumulative Transactional carrier remains source-private. H1b adds private exact transport and four bounded installed observations; all four remain partial and the 250 required contracts remain visible. No public Transactional runner admission or whole-contract credit follows.

The package guard now inspects actual module exports and the closed package subpath map, rather than searching source text for private symbol names. The configuration test retains pre-setup refusal for malformed exact configuration, permits valid Read+Update and private Transactional modes, and keeps the ordinary-runner private-brand boundary.

The planner now returns `transportAdmission: "private-exact-available"` for Transactional alongside structural `ready-unexecuted` rows. This is not a new public API or an executable admission flag; it identifies the actual private transport. Coverage observation status is independent, and whole-contract flags remain false. Coverage-binding tests require an actions array and strict structural equality, preventing an omitted assertion list from comparing equal to an undefined property.

Two review suggestions are bounded rather than generalized into new mechanisms. Cumulative catalog IDs have exactly two guarded private callers; hypothetical future-profile hardening is deferred until another caller exists. Canonical selection refusal is a factory-identity boundary, not an independent content-completeness validator: both copied and trimmed records are refused because neither is loader-branded. Existing coverage follows from the immutable canonical loader, not the trimmed-record probe alone.

Read+Update retains its existing carrier and transport behavior. Protocol/catalog/public profile admission are unchanged; cumulative Transactional qualification remains open.

## Installed observation boundary

The private launcher supplies explicit canonical Scope, caller-provisioned isolated store directory, captured contract artifacts, and generated credentials to the installed child over inherited IPC. The child reports its actual immutable runtime, payload, contract, authentication and policy identities. Preparation and reopen compare those facts before actions. This is configured-target evidence, not cold discovery: required Transactional discovery and the remaining catalog obligations still need qualification.

The runner registers a receipt target only from a canonical mutation response containing a schema-valid receipt `/id`, captured alongside complete exact request and response wire evidence. It retains the original source action, credential handle, response digest and session identity. Receipt GET/HEAD uses a one-target raw route table bound to the current validated physical session; it records a separate dynamic configuration digest without changing the run's base configuration. Reopen preserves original receipt provenance while rebinding ordinary and dynamic traffic. These metadata fields are excluded from legacy report-v3 types, runtime assertions and serialization.

Four small fixtures exercise atomic commit and ordered Events, failed-batch rollback, retained completed/failed receipt reads after reopen, and a retained failure after graph state changes. Collections declare limit 32 and require no next page; Event inventories also require no next page. They use at most six induced Scope Events per row. Requests use header/body caps of 16,384/65,536 bytes; response header/body caps are 65,536/1,048,576 bytes with a 2,097,152-byte wire-evidence ceiling. This observation does not qualify larger receipts, general receipt paging, dependency/alias behavior, catch-up, Snapshot, changefeed, owned transitions, or the remaining required contracts.

The new metadata-comparison whitelist entries (`bdp-scope-epoch`, `bdp-authorization-view`, `bdp-scope-position`) compare existing response headers using the existing assertion grammar. They do not expand request authority. On ordinary non-abort cleanup, the session aborts/drains registered dynamic requests before signalling child shutdown; installed shutdown or IPC disconnect releases the owner for a subsequent ordinary reopen. Forced termination remains failure, not successful observation.

## Installed review follow-up

The cohort now carries a cooperative 90-second aggregate deadline through bootstrap, preparation, ordinary requests, dynamic receipt requests and reopen. Preparation/reopen has a 10-second end-to-end lifecycle budget; raw session cleanup has an explicit 10-second bound inside that remaining parent budget, and each wire request retains its 5-second bound. Close and reopen do not each receive a fresh additional 10 seconds; launcher cleanup bounds and the aggregate signal remain nested. Other raw targets retain the prior cleanup default of requestTimeoutMs, or 30 seconds when absent. The 120-second test timeout is a final test-run guard. Abort can concurrently initiate child close and request cancellation; pending work settles before final cleanup resolves, without a strict drain-before-child-signal ordering claim. Separately bounded emergency cleanup may finish after the work deadline; the helper cannot publish success after abort. A short-budget negative witness waits after real wire bytes arrive, then verifies rejection, child termination and absence of late publication.

Ordinary Resource `/id` captures remain ordinary bindings. Receipt authority comes only from the actual canonical mutation response validated together with source route, schema and wire evidence. Ordinary captures do not grant receipt-follow permission. The original response digest records wire provenance; no unused wire buffer is retained. Subsequent header/context changes are legitimate, so later raw response bytes are not required to equal the original response. Registration mismatch controls remain separate from the original receipt equality check.

Private input, ledger and session refusals report safe harness-error reasons. Actual target status/assertion failures remain failures. Dynamic configuration, source receipt and current session metadata are attached when the raw exchange is recorded, including failed exchanges. Dynamic response limits come from the validated active session binding. All three serving-context headers now have explicit presence assertions alongside equality checks, so equality of two absent headers cannot qualify the observation. The artifact-identity negative control uses a well-formed different digest.

The actual installed negative observations and the smaller synthetic runner/lifecycle checks serve different purposes. Neither broadens the four partial rows or provides whole-profile credit. The historical frozen observations remain unchanged; a successor source requires a fresh installed observation.


## Final harness supplement

Receipt evidence self-disagreement and missing validator/session infrastructure are harness errors with fixed safe reasons. A real target receipt that fails its schema or differs from its retained original JSON facts is a target failure, also with a fixed safe reason. Private helper error types carry that distinction without importing runner classes or exposing raw bodies. Only canonical mutation responses grant receipt authority; dynamic reads neither capture nor regrant it. Construction-time session metadata is the sole attachment point, including failed exchanges.

Cleanup errors consumed into runner row diagnostics are retained separately by the installed cohort wrapper. Any child/session cleanup failure intentionally refuses publication of the entire cohort, even if a complete row result exists. Dirty observations are not returned. If abort and cleanup both fail, the final AggregateError preserves the original abort and the actual cleanup cause; tests traverse causes rather than matching only its top-level message. Response-limit constant consolidation remains deferred: current fail-closed literal checks are defensive, not a duplication cleanup or new runtime guarantee.


Construction validates a supplied request timeout independently of cleanup timeout before starting a session. Unsupported non-200, absent-wire and oversized source observations are refused before wire self-consistency comparison; this adds no supported response status. Both deadline witnesses use the same cause traversal. The cleanup and child-close bounds may both be 10 seconds, with reopen constrained by the remaining parent budget; they are intentional nested limits, not a guarantee that every phase can consume its full bound. No deadline or observation budget is widened by this closure.
