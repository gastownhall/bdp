## Informative and proposed material

The [canonical CLI](../cli-design/bdp-cli.md) is the developing command specification; its [overview](../cli-design/bdp-cli.md#overview-authoring-sections) is informative narrative. Common field masks and revision/Reference syntax map to the selected contract, with product conveniences explicitly distinguished. Existing historical review receipts preserve their exact reviewed subjects.

[Query](../../specs/profiles/core/query.md), [structured native reads](../../specs/profiles/core/read-operations.md), [query language](../cli-design/query-language.md) and their design schemas remain **proposed** where they specify structured List/Graph/Query transport or first-slice encoding. Selected logical directions do not advertise that operation. The selected native projection capability uses `projectionVersion`; the proposed POST operation uses `readVersion` and needs independent coherent adoption. No general Query implementation is required for the selected projection unit.

The [batch overview](../cli-design/overview/06-batch.md) records selected design directions for bindings, arguments and atomic transaction selection. Its richer encoding and [transaction selection input proposal](../cli-design/query-ir/transaction-selection-inputs.md) are **proposed**, not permission to widen six-CRUD atomic batch version 1. A later independently selected binding must preserve the earlier version's admission and guarantees. Parameterized installed commands/queries and a CLI-backed server remain future work.

Recovery/replication checkpoints, receipts, replica bootstrap and public epoch machinery remain **deferred** under retained Core/Write. Ordinary inventory snapshots and Event replay do not silently import them. This source alignment makes no frozen consumer, runtime, release or evidence-pin update.
