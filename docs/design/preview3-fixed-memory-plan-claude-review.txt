### 2. High — Required subset / F0 (lines 41–42, 91): exact-revision conformance machinery earns nothing for a fixed catalog
**Issue.** `typegraph` is a 210-line evaluator keyed on `Key{ID, Revision}` computing exact-revision closure over a DAG with per-revision ancestor snapshots (`CONTRACT.md`: "A future loader must capture direct declarations from each source revision's recorded owned state"). The Preview 3 catalog is one revision per type and one level deep — five types conform to Memory, six Links conform to nothing. Membership is a literal parent map.
**Impact.** Importing revision-keyed closure machinery into F0 buys a `map[string]string` lookup at the cost of a loader contract, revision plumbing and a second conformance implementation alongside the shipped descriptors. This is the "machinery that earns nothing" pattern.
**Fix.** Specify F0's membership as a compiled table derived from the same `ConformsTo` values F2 installs in the descriptors (`graphops/types.go:812-884`), with a test asserting table and descriptor agree. State explicitly that exact-revision conformance is **not** in Preview 3 scope.

### 3. Critical — First coding assignment (lines 91, 116–118): fixture provenance is undefined and the stated cross-check does not exist

**Fix.** Name the artifact and the act: F0 step 1 vendors `fixtures/specs/memory/schema-cases.json` and the eight schema JSONs **from `38791e4c`** into the beads tree with source commit/path/hash recorded and a `nonnormative` label; acceptance is the **72 property-shape cases** plus named extras. ### 6. High — Required subset (line 45) / F3 (line 94): "allowed endpoint pairs" has no representation in the shipped descriptor, and the plan never names the fork
**Issue.** `graphops.EndpointConstraint` (`graphops/types.go:617-639`) holds one independent `conformsTo` **conjunction** per end plus an `ExternalPolicy`. There is no union-of-pairs form, and descriptors are persisted as canonical JSON with a fingerprint. The requirement "both ends must satisfy the same pair arm" (code-audit:21 item 3) is therefore either (a) a compiled predicate living outside the descriptor, or (b) a descriptor wire-shape extension plus new fingerprints.
**Impact.** Option (b) is a persisted-representation change the plan's own exclusion list appears to forbid; option (a) means the persisted descriptor under-describes the rule actually enforced, so `bd types --details` (`cmd/bd/graph_preview_types.go:24-30`) advertises a weaker constraint than the runtime applies. The plan silently leaves the worker to choose.
**Fix.** State option (a) explicitly: pair constraints are enforced by compiled per-type predicates; the persisted descriptor keeps the Preview-2 independent-endpoint shape; and inventory/details output must not claim a correlated constraint it does not carry. Add a test that the predicate is strictly narrower than the descriptor.

### 7. High — Source findings (lines 83–85) / F2 (line 93): the existing catalog admission is exact-count, and old-workspace disposition is a missing product decision

### 8. High — F2/F3 boundary (lines 93–94): half-installed catalog is an invalid store, so installation cannot be split across slices

### 9. High — F1 (line 92): "preserve unknown properties" and "no relaxed strict decoding" are the same decoder, and they contradict
**Issue.** The shipped decoder rejects anything other than exactly two fields: `if len(fields) != 2 || len(fields["title"]) == 0 || fields["title"][0] != '"' …` → "final preview Memory properties require exactly title and body strings" (`internal/storage/graphstore/memory_properties_patch.go:69-70`). F1 simultaneously requires "preservation of specialized and unknown properties" and "no … relaxed strict decoding for legacy/native records."
**Impact.** Unreconciled as written. A worker can satisfy either sentence and claim conformance; the likely outcome is that unknown-root preservation is dropped (the audit calls out "unknown open-root properties" as requirement 1, code-audit:23) or that the strict refusal is weakened for *all* records.
**Fix.** Write the rule: the exactly-title-and-body check is replaced by per-type schema-complete validation; open-root unknown properties are **preserved** for Memory-family types; malformed/non-object payloads still refuse. Name `TestMemoryPropertiesPatchLifecycle` and the refusal-text test as deliberate migrations.
