# Bound waits for known ordinary collection continuations

This follow-up to PR209 selects ordinary Bead and Link collection continuations whose first attempt genuinely validates the emitted cursor and its saved query prefix, with a known minimum in the same epoch and authorization view. It changes the service retry path, not the replication Snapshot protocol or the ordinary retained-query cache engine. The agreed specification is unchanged.

The existing pagination contract keeps the original query selection, projection, rows, revisions, continuation and absolute expiry. The minimum-position contract forbids serving a page below its minimum and already defines a bounded catch-up-timeout. Live position2 cannot make a query saved at1 eligible for minimum2. The service therefore retries the same captured continuation under the existing single finite deadline. It neither reanchors to live state nor extends retention to make timeout more likely.

Each service operation creates its own retry closure. The first successful ordinary authority result supplies the actual saved context; no caller/provider assertion establishes that binding. Later successful results must retain exactly that saved epoch, view and position. Every attempt still performs the ordinary owner authorization, cursor/projection/TTL checks and saved-source publication fence. No owner entry survives the wait. Abort/lifecycle behavior and the original wait clock/budget remain with the existing service waiter.

A saved prefix behind the minimum throws the existing private behind signal with the CURRENT serving context. This distinction matters: the selected data remains at1 while a timeout response can correctly describe the current serving entry at2. If the finite deadline expires while the original cursor remains valid and ineligible, the existing HTTP mapper emits503/catch-up-timeout, unavailable/after-delay, Retry-After1 and the actual current error context. Conditional304/412 cannot bypass eligibility.

Once a valid binding exists, a genuine subsequent ordinary cursor refusal is returned unchanged. Actual TTL expiry or invalidation/eviction can therefore terminate with the native cursor-expired410/after-state-change before timeout. There is no synthetic expiry, automatic replacement cursor or retention renewal. Erasure invalidates the actual cache and retains the saved-source publication fence. If the cursor is already unavailable before the first valid binding, this tranche leaves the earlier private unsupported boundary in place; it does not infer a new precedence rule from a missing saved context.

The source-private one-shot plane minimum facet keeps its existing unsupported behavior for higher minima. The externally used service explicitly creates the waitable operation closure. Type/incident continuations, unproved minima, foreign initial contexts, unknown tokens and replication Snapshot collision branches remain outside this selected slice. This is a bounded behavior addition, not whole-profile minimum-read qualification.
