# BDPv0.1 Core/Write disposition map

**Non-normative consolidation proposal.** This is source accounting for the first bounded documentation patch, not the adopted BDPv0.1 contract or another delivery tracker. [BDP #59](https://github.com/gastownhall/bdp/issues/59) is the sole shared consolidation plan. [specs/](../../specs/README.md) remains the only normative authority.

Trish owns the shared `codex/bdp-v0.1` integration branch and Types/Type definitions. Sybil owns Core/Write factoring, the canonical CLI and Experimental. The starting commit is [`37d6622f95e71cac022478cfbcb3e8f2d6bdf444`](https://github.com/gastownhall/bdp/tree/37d6622f95e71cac022478cfbcb3e8f2d6bdf444). Branch creation does not make inherited text a coherent or adopted v0.1 specification. Implementation, `bd serve`, downstream pins and release reconciliation do not resume through this patch.

## Retained responsibilities

| Surface | Candidate responsibility |
| --- | --- |
| Core/Read | Resource/Reference representations, revision meaning, discovery, ordinary reads/list, recognizable errors and the required Event observation foundation |
| Write | Six CRUD operations, alias duties, atomic mutation decisions, guards, durable outcomes/retries and committed required Event facts |
| Optional atomic batch within Write | The same CRUD mutation vocabulary, staged creation identities, one atomic commit and bounded complete outcomes, independent of replication |
| Types, owned by Trish | Complete affiliation/conformance/definition semantics and conditional validation, reconciled with same-identity retyping and final-graph rules |
| History | Exact retained-version access and truthful retention/erasure dispositions; independent of replica synchronization |
| Experimental | [Non-normative deferred explorations](../../experimental/README.md), outside specs/, with no required-profile dependency or implementation promise |

Required Events are not deferred. Keep their reliable committed facts, transaction association, ordering, authorization and replay/retention/refusal foundations. Replica bootstrap, complete state reconciliation and applied checkpoints are stronger separate promises. Removing non-atomic sequence must not remove safe-write rules nested beneath its heading. Moving public receipt URLs must not remove the internal durable key/outcome ledger.

The canonical CLI remains a stress test of the shared operation model: default Scope context, Scope-defined IDs, root Bead verbs and Link verbs, contextual --type/--exact-type, unified object edits and shared batch/CLI JSON. Delta Events should reuse corresponding batch mutation fields and edit semantics, with resolved identities and actual prior/resulting revisions. This is no commitment to Event-to-command resubmission or a newly adopted wire schema. Detailed CLI text will be integrated as a separate bounded candidate; this patch does not copy the private paper packet wholesale.

## What this first patch does

It adds Experimental front matter and three short explorations, and records every level-three heading and nested sequence subsection of the pinned Write source below. It changes no normative prose, discovery value, JSON schema, protocol implementation, conformance applicability or existing evidence. The linked pinned source is retained intact; no section has been silently deleted by a file move.

Subsequent extraction must settle the retained contract with coordinated prose/schema/example changes. New normative changes require an existing/reused concrete BDP issue under #59. This accounting is not a waiver of any obligation when a service advertises the existing cumulative-v0 profile.

## Decisions still visible to Donna and the owners

Close contract/version selection and the real migration boundary; complete portable References/local equality and trust; freeze the base Type-affiliation representation; settle inline outcomes, durable retry/restore and optional batch in-flight/results; and close required Event read-only duties, baseline representation and replay/live/retention contract. Experimental can remain incomplete. Do not build a compatibility fleet, extension framework or implementation campaign to resolve this documentation patch.
