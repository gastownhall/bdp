# Memory provenance: product evidence audit — October 11, 2026

Status: source inspection for the Memory proposal terminology investigation. This note proposes no implementation or release change. No runtime tests were run and no database or binary was opened. All product conclusions below are bounded by the inspected public interfaces and implementations, not a claim to have audited every extension or deployment.

## What matches the proposal, and what does not

| Proposal concern | Shipped v1.3.1 evidence | Assessment |
| --- | --- | --- |
| Durable remembered text | Keyed `Remember/Recall/Forget/List`, values stored under `kv.memory.` in config | Present as legacy key/value memory; not first-class canonical Memory Beads |
| Exact historical Memory citation | Recall accepts only a key; result is key/value/found; no version selector or version identity | Proposal target absent from this public Memory surface |
| Change Attribution for accepted Memory versions | Memory requests carry key/content, no actor or revision; underlying Dolt commit routes differ | Provider history must not be mistaken for the proposal’s portable per-Memory attribution contract |
| Inception and content derivation | No typed fields in the keyed Memory record | Not supplied by this Memory contract; text could carry a convention without shared interpretation |
| Decision-to-evidence relationships | Issue provenance supports an explicit `used` kind and opaque external ref/payload | A useful rough recording primitive, not pinned Memory evidence or a standardized decision rationale model |
| Change feed | Journal supplies ordered committed issue mutation snapshots | Present for bounded clone-local replay, not complete Memory History or retained provenance assertions |
| Governance | Deployment bearer gate; CLI read-only guard; operator retention configuration | Specific controls exist. They do not establish verified actor identity, per-Memory policy, mandatory review, or a general governance subsystem |

### Legacy Memory remains materially narrower than the proposal

The public [Memory contract](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/memoryops/memories.go#L5-L198) exposes keyed strings, not canonical Bead identities, pinned revisions, structured derivation, or revision authorship. Its transaction-level [implementation](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/storage/memoryops/memories.go#L20-L31) explicitly describes differing Dolt commit behavior across routes; its [storage encoding and writes](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/storage/memoryops/memories.go#L45-L106) use config rows. This does not mean no underlying historical evidence can ever be recovered; it means ordinary Memory readers do not receive the proposal’s exact, portable citation contract.

[Current main’s corpus budget](https://github.com/gastownhall/beads/blob/7477ec1352d9380b692773bc3c2e66ae2e60ae37/cmd/bd/memory.go#L439-L506) is explicitly a front-door policy that HTTP POST does not inherit, and its read/check/write is advisory rather than atomic. Call this an operator guardrail, not enforced cross-surface governance. Shipped [prime guidance](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/cmd/bd/prime.go#L109-L122) still injects memory bodies with optional caps; the proposal’s selective-retrieval exposure posture remains a target.

### Existing “provenance” means issue-to-artifact activity records

The [CLI](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/cmd/bd/provenance.go#L15-L26) offers `record`, `log`, and `by-ref`. The [record shape](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/types/types.go#L1663-L1702) contains issue ID, kind, actor, external reference and reference kind, payload, source, event time and ingest time. Allowed kinds are `cut`, `claim`, `suspend`, `resume`, `handoff`, `commit`, `land`, `used`; classified references are Git SHA, PR, work ID, transcript, branch. `ref_kind` is optional, so an unclassified opaque reference is also possible; that flexibility does not create typed Bead/Link references.

This supports post-facto recording and artifact lookup. It **does not identify a subject revision**, admit a Link subject through its typed API, or supply an independently versioned provenance assertion. The [SQL schema](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/storage/schema/migrations/0063_create_provenance_events.up.sql#L20-L35) binds `issue_id` to `issues` and cascades deletion. No subject revision column exists. Its source/actor values are supplied claims, not authenticated evidence.

The [idempotency key](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/storage/issueops/provenance.go#L85-L144) hashes `source:issue:kind:(ref or occurred_at)` and uses `INSERT IGNORE`. Payload and actor do not participate. Re-recording the same key with corrected payload does not correct the original. There is no individual update/retraction operation. Consequently, the newly discussed versioned Provenance Bead is a substantive new model, not a rename of this table.

The [ADR](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/engdocs/adr/0003-provenance-event-log.md#L11-L37) explains the intended question: what happened in the work lifecycle and which external artifact it was bound to. Its status still says Proposed; executable code/schema above, rather than that status label, establishes shipment. Chris’s [naming comment](https://github.com/gastownhall/beads/issues/5877#issuecomment-5472794536) explicitly renamed proposal “Stored Provenance” to “Inception” because this existing command/table already occupied the word. That naming collision does not make Inception equivalent to all provenance.

### Journal, audit history, and provenance answer different questions

The [journal’s introduction](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/docs/reference/events-journal.md#L6-L60) distinguishes field-change audit history from machine replay. Journal records carry sequence, insert time, operation, issue ID, optional actor, resulting issue snapshot, and dependency/comment payloads ([record schema](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/eventsjournal/record.go#L32-L66)). None is a first-class stable resource revision address.

It is disabled by default, does not backfill on activation, and normally retains the larger of seven days or 100,000 records. It reports truncation rather than silently skipping a pruned prefix. Its [documented boundaries](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/docs/reference/events-journal.md#L434-L482) exclude sync/merge, raw SQL, compaction and restore; sequence spaces are clone-local and journal tables are not replicated/versioned. It records mutations, not which information a reader actually consumed or why a decision was made. It can transport or observe changes to future provenance records; it cannot substitute for their domain meaning or retention contract.

### Governance: distinguish controls from attributed claims

Shipped HTTP [authentication](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/httpapi/spec/openapi.v0.yaml#L135-L169) is a deployment option. A configured shared bearer grants access to the whole surface; [the API explicitly says](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/httpapi/spec/openapi.v0.yaml#L2537-L2553) it names nobody and cannot verify the supplied author. The [deletion contract](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/internal/httpapi/spec/openapi.v0.yaml#L7440-L7446) likewise says no narrower right is granted. The public [Memory role](https://github.com/gastownhall/beads/blob/c1c4b642ac1c08d8c828007a1c2f96e47e43ef7c/memoryops/memories.go#L136-L144) calls read-only mode a uniform front-door guard, not a provisioned read-only Memory entitlement.

That is evidence of specific present controls and their limits, not proof that no deployment can layer external authorization. Proposal R29 deliberately leaves governance shared and optional; R27a specifies exposure behavior, and R30 leaves truth/applicability judgment to tools. Do not turn the existence of attribution or a metadata bag into claims of authenticated authorship, approval policy, or knowledge quality enforcement.

## Preview 2 is closer, but still a distinct implementation slice

At the inspected fork staging pin, [Memory records](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/storage/graphstore/types.go#L44-L78) have canonical ID, Type, revision/version, title/body properties, metadata, owned Links and attribution. [Exact retained reads](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/storage/graphstore/history_exact.go#L18-L32) exist, but explicitly disclaim complete public History. [Links](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/storage/graphstore/types.go#L114-L126) still have unpinned live local endpoints. The [comparison implementation](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/storage/graphstore/history_compare.go#L137-L143) explicitly reports Memory inception and derivation as unsupported. General metadata can carry application conventions; it is not the same as implementing those proposal fields.

The [wire projection](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/httpapi/graphread/reader.go#L173-L192) maps stored claimed attribution to `basis: writer-supplied`, preserving the distinction from verified origin. The [reader](https://github.com/donnabox/beads/blob/76fde9c9cb0865d430bf12d76fc473490f51128a/internal/httpapi/graphread/reader.go#L25-L28) does not select historical versions. These are positive partial building blocks, not evidence that revision-pinned decision evidence, full Memory conformance, or the proposed Provenance Bead Type has shipped. Some draft CLI specification NYI rows lag integration; the executable structures above and explicit release staging status are the stronger evidence for this comparison.

## Recommendation for the parent synthesis

Name the concerns separately: **change attribution** (who accepted/wrote this revision), **ingestion origin/Inception** (how the record reached this store), **content derivation/lineage** (what inputs produced this content), **decision evidence and rationale** (what supported or challenged a decision and why), **activity audit** (what happened), **change feed** (what a consumer must replay), and **governance** (rules, authority, stewardship and enforcement). The proposal asks primarily for durable, exact, attributable knowledge and explicit evidence relationships, while leaving most governance outside its scope.

Keep the proposed Provenance Bead for post-facto, correctable claims about exact revisions. Preserve native per-revision attribution and operational journals as separate mechanisms. For “decision D@r was based on evidence E@s,” model the exact inputs and relationship meaning; recording that E was read or appears in a receipt establishes exposure/usage evidence, not by itself that E justified the decision or that the decision was correct.
