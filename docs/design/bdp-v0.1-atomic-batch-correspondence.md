## Concrete author choices

The retained batch is independently optional within Write and always atomic, using
six ordinary CRUD records with existing name/@name identity capture. Sequence,
set writes, aliases in batch and public pending/paged receipts are excluded. The
old Transactional machinery remains explicitly inherited staging source. No new
profile literal or Experimental commitment is selected here.

| Choice | Resulting contract |
| --- | --- |
| Capability identity/version | `https://github.com/gastownhall/bdp/capabilities/atomic-batch`, exact `"1"`, feature-owned operation/support/bounds detail |
| Critical selection | Required `capabilityVersion:"1"` in the batch wrapper, generated by CLI; no ignorable header/default/fallback |
| Supported subset | Nonempty subset of six recognized CRUD names; valid disabled member uses deterministic first-index refusal |
| Unknown vocabulary | Unknown/deferred set names are malformed in version 1, not accidentally enabled by inherited eight-operation definitions |
| Refusal | Feature-specific request-family HTTP 422/after-state-change Problems with exact capability/operation and pointer fields |
| Native success | Complete inline results with operation/index/create-name, authoritative changed flags, and opaque transaction correlation only when effectful |
| Singleton Resource result | Required changed flag shares the ordinary member contract; aliases remain distinct |
| No-op/ordering | Durable successful all-no-op has false/no transaction; explicit A→B→A transitions cannot collapse to final equality |
| Cross-carrier key | One key namespace, but selected batch context differs from singleton, so switching an existing key conflicts rather than executes again |
| Creation labels | Normalized creator slots ignore label spelling; retained replay projects requested create-name by index, with fixed identities/outcomes/transaction |
| Recovery | Retained identity/outcome precedes current support; internal in-flight state uses existing retryable Problem/wait, never public pending receipt |

These are authored choices for review, not invented human approvals. Cross-carrier
equality deliberately differs from old v0 Transactional because selected capability
versions are execution context under the binding. The old guarantee remains
explicitly scoped to old v0; new requests do not reinterpret a known key as fresh.
The original #152 valid-but-unsupported set-operation example belongs to its older
eight-operation baseline: current version 1 recognizes six, and a future explicitly
selected version can add vocabulary. No set implementation or general template
language is smuggled into this cut.

CLI command files use the recovered ordinary token/value model, never a shell.
The four paper command files serve as inputs and proposed canonical renderings of
the same request; compile/render equations preserve exact values, field presence,

offline and makes no support/admission claim. Native result examples are paired
