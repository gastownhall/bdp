## Remaining finding

1. **Medium — `docs/cli-design/query-ir/fixtures.json` (`pins`) and `cases.json` (`resource-edition-equality`, `resource-identity-only`): adding source-pin fixtures invalidated two older expected result sets.** New Links `pin-old-source` and `pin-current-source` both target the floating `pin-root`, so each has a different-Link witness with the same target edition `pin-root@r1`. Consequently `resource-edition-equality` must now return `pin-current-source` and `pin-old-source`, rather than `[]`. `resource-identity-only` must now return all four Links (`pin-current-source`, `pin-fixed`, `pin-floating`, `pin-old-source`), rather than only `pin-fixed` and `pin-floating`. These predicates scan the whole Link fixture and compare acquired targets; the new edition-applicable traversal rule does not exclude either new Link from that scan. **Impact:** a correct evaluator would fail authored acceptance cases, while the static checker still passes because it does not evaluate expected results. **Fix:** update both expectations or isolate the new incidence Links in a separate fixture. Audit other cases that share this fixture when adding further Links. I independently confirmed these two sets with a read-only calculation over target identities/current-or-pinned revisions; that calculation was not a general query evaluator.
