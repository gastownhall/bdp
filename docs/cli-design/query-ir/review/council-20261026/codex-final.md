# Native Codex final bounded review

Reviewed the live author tree at `/private/var/tmp/melinda-canonical-read-design-20261026`, focusing on capability flags, native binding/schema, CLI/projection correspondence, and the amended authored cases. No source was changed. The only new artifact is this report. This was a source review with the small extracted-function checks described below; no CLI parser, full evaluator, HTTP service, provider, or product benchmark was executed.

## Remaining concrete findings

1. **High — `docs/cli-design/query-ir/read-binding.schema.json`, `$defs.problem`: closed top-level properties make an inherited History refusal unsatisfiable.** The schema retains the inherited conditional that `code:revision-unretained` requires a `missing` member with `historyMissing` shape. However, the newly closed Problem object has `additionalProperties:false`, and `missing` is absent from its top-level `properties`. A property declared only inside a conditional allOf branch is still an additional property for that top-level keyword. Therefore no revision-unretained Problem can satisfy this schema. A resource-pruned Problem carrying its permitted archivedAt Reference is likewise rejected because archivedAt is only declared conditionally. The held native readProblem intentionally omits this closure. **Impact:** correctly preserving History/retention diagnoses, as the native prose requires, conflicts with the new response schema. The 48 wire cases do not cover these inherited extension members. **Fix:** preserve the inherited Problem extension policy, or declare every supported conditional extension at the appropriate scope/use unevaluatedProperties with correct composition. Add positive revision-unretained-with-missing and resource-pruned-with-archivedAt cases, as well as the existing forbidden-member negatives. This finding follows JSON Schema keyword scope; I did not execute a jsonschema validator in this pass.

2. **Medium — `docs/cli-design/query-ir/validate-binding.py`, `semantic()` nested `nodes()` walker: capability admission interprets literal JSON data as AST nodes.** The walker recursively visits every JSON object and treats any `op` key as a node, including content inside `literal.value`. A valid List equality comparing metadata.payload to literal `{"op":"walk","depth":"unbounded"}` is admitted by the AST checker but incorrectly refused as an unsupported unbounded walk on a List-only provider. Literal `{"op":"typeIs"}` instead raises uncaught KeyError('match'). Both are ordinary allowed JSON comparison data; they do not request traversal or Type-family interpretation. **Impact:** generated JSON requests have data-dependent false capability refusals or checker crashes, and the new capability admission checker cannot serve as the intended bounded reference. **Fix:** traverse actual AST child positions and stop at literal nodes; do not inspect literal.value, arbitrary comparison objects, or path data for tagged executable nodes. Add positive cases with op-bearing literal objects under all-declined List capability flags. I independently reproduced both outcomes by executing only extracted admission functions against in-memory ASTs; this was not a query evaluator or backend run.

## Checks without further blockers

- The capability booleans now let a small List-only implementation decline count, masks, family checks, pinned acquisition, sort and unbounded traversal. The prose distinguishes carrying/testing stored Reference data from acquiring a pinned Resource. Point projection has its own capability and does not require a List endpoint. Current/exact point support and History prerequisites are explicit.
- The native wrapper consistently uses limit for per-fetch sizing; CLI page-size and client total-limit remain distinct. Continuation operation routing is retained in state rather than duplicated in query parameters.
- Graph-profile routing and general Query support are separated. Graph results additionally require the advertised graph profile even under a Query-profile body. The capability schema now rejects unboundedTraversal:true when neither traversal profile is offered.
- Full versus projected Resource item arms are conditional on actual projection metadata; their field-shape schemas and separate contextual semantics are identified. Count/graph limits and graph sort restrictions appear in the candidate request schema.
- The flag lowering table now includes both stored Reference union arms for from/to, the source-or-target combination, shared alias use, presence, Type tests and outer controls. I found no new mismatch in those stated lowerings.
- Lazy Resource pages remain scoped to proven members and an exact stable-order boundary, while count/graph and any/all retain their required whole-result or definitive proof obligations. No new permission to turn cutoff into a negative/universal proof was introduced.
- The two pin-fixture oracle corrections from my previous follow-up are present: edition equality selects the two source Links; identity-only equality selects all four. The live corpus contains 129 AST cases and 48 wire cases. These counts and expected sets were inspected, not a claim that all semantic outcomes were executed.
- The overview uses an explicit detail format for the graph tree, and the corrected Query table follows the common collection default. Its missing-state and revision continuity changes remain tutorial examples rather than runtime transcripts.
