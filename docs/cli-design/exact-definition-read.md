# Canonical CLI: exact definition interpretation seam

Paired common source for existing #282/#279/#280 and sole #59, following the
[read surface](reads-and-paging.md) and exact Types candidate
[PR283 at 8fc7ce9](https://github.com/gastownhall/bdp/blob/8fc7ce901f747587d352091d7110050059d3dc49/specs/profiles/types/exact-definition-read.md).
This defines how a feature-aware interpreter obtains an exact definition; public
Type commands remain deferred, with only `bdp type list` retained as a placeholder.
It does not claim that the entire Type wire surface already has a public CLI verb.

## Exact intent and interpreting context

A typed-affiliation interpreter has an exact `{uri,revision}` and an explicit
interpreting Scope. Discover that Scope's version 1 type-definition-read operation
and make [the selected lookup](../../specs/profiles/core/type-definition-read.md).
Preserve the URI/revision and the resulting definition/origin wrapper. The Scope
is the interpretation context, not a claim it owns the referenced definition.

| Semantic input | Lowering |
| --- | --- |
| Explicit interpreting Scope | Verified discovery, selected BDP contract and capability version 1 |
| Exact Type Reference | Query `uri` and `revision`, with normal form-query encoding |
| Selected feature | Required query `capabilityVersion=1`, generated by the adapter |
| Dependency in recorded declarations | Another exact lookup in that context, with visited exact-pair tracking |
| Complete native lookup result | Preserve `definition` plus recorded `originScope`; no unwrapping into an ordinary owning-Resource result |

No shell/request escape, Type-prefix heuristic, inventory scan, implicit origin
fetch/register or current/default substitution is involved. Missing child/parent
reads are real refusals, never a partial closure success. A successful child read
alone does not establish complete interpretation. Ordinary write `--type` resolution
and guard semantics are unchanged; this read is not a new default-acquisition step.

## Keep ordinary show meaningful

`show ID@=TOKEN` remains an ordinary exact Resource read
under its advertised application History contract. Missing History MUST NOT silently
route that generic command to a different interpreting Scope's definition lookup.
A configured Scope is not proof of ownership or Type-definition intent. `@current`
conveniences on ordinary CLI References do not turn literal lookup query tokens into
instructions: the wire requires an exact token, including a literal `current` token
when that is what the caller authored through an explicit token field.

A later Type CLI must expose the exact-definition intent/context and preserve the
wrapper/origin contract, then pair its usable command signature with this wire
operation. That remaining CLI coverage is an explicit completion gate, not a hidden
`type show` command or permission to revive Type lifecycle/CRUD design here.

The [local intrinsic materializations](../../specs/profiles/types/types.md#24-ordinary-local-records-for-shared-intrinsic-definitions)
selected for the first Types sequence do not change this lowering. Ordinary show
of their actual local IDs reports genuine local Resource identity/ownership.
Lookup of a shared global exact pair still returns that unchanged global definition
and wrapper, with originScope absent when unrecorded. Checked correspondence is
not URI equality or a local Type alias; neither operation silently substitutes for
the other. Public correspondence transport remains unselected, and a native
preview's trusted context is not a claim of complete Types1 provider support.

## Output and errors do not invent ownership

The operation wrapper is neither `resource` nor `resource_collection`. It supplies no
Resource/Collection kind header. `originScope` is recorded source context, not the
receiving Scope or a verified current mutation destination. Any service-desc describes
the lookup service. A future CLI descriptor must retain those distinctions; the
ordinary-read [framing subset](read-framing.schema.json) is not extended by relabeling
this wrapper. Current generic HEAD metadata remains metadata, not a fake definition.

Preserve actual Problems unchanged. Unsupported feature versions refuse explicitly;
no generic-JSON/current/History fallback. Narrow `revision-unretained` needs positive
loss evidence plus current whole-definition/owned-state disclosure permission. It
does not require general History, fabricate provenance or grant an absence oracle.
Temporary backend failure stays service failure. No output projection, paging of
owned captures, flattening of recorded Refines state or all-closure response is added.
